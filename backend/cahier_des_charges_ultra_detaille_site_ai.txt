Ce document formalise de facon exhaustive les besoins fonctionnels, techniques,
organisationnels et qualitatifs du systeme global compose de:
- Frontend web Angular (portail public, patient, medecin)
- Backend Spring Boot (API, regles metier, orchestration, persistance)

Ce cahier des charges est concu pour:

- Permettre une industrialisation progressive (MLOps, securite, observabilite)

====================================================================
1) CONTEXTE ET VISION PRODUIT
====================================================================
1.1 Contexte metier
Le projet cible la prise en charge de patientes atteintes (ou suspectes) de
pathologies mammaires/cancer du sein. Il vise a centraliser:
- Le suivi clinique longitudinal (tracker, traitements, alertes, timeline)
- La coordination patient-medecin (liens, RDV, documents, messaging)
- L'assistance IA (chat educatif, analyse mammographique, prediction risque)

1.2 Vision
Offrir une plateforme numerique unifiee, orientee securite et aide a la
decision, sans jamais remplacer le diagnostic medical humain.

1.3 Positionnement clinique et legal
- Outil d'aide a la decision et d'education
- Non substitut a un diagnostic medical
- Les sorties IA doivent etre interpretees et validees par un professionnel
- Les mentions de limitation d'usage doivent etre visibles dans l'interface

6) IA #1 MAMMOGRAMME (SAFE SCAN) - ULTRA DETAILLE
====================================================================
6.1 But fonctionnel
Analyser des mammographies (DICOM ou image standard) pour:
- Detecter lesions (ex: mass, calc)
- Segmenter zones suspectes
- Classifier lesion (Benign/Malignant)
- Fournir visualisations + features radiomiques
- Produire un rapport textuel de conclusion

6.2 Stack IA
- FastAPI
- PyTorch/Torchvision (Mask R-CNN + backbone ConvNeXt/FPN)
- Keras (extracteurs DenseNet121/ConvNeXtTiny pour classification)
- SVM (joblib) + scaler
- OpenCV, pydicom, scikit-image
- OpenRouter LLM (fallback local si cle absente)

6.3 Endpoints IA
- GET /health
- POST /predict (multipart file + pixel_spacing)
- POST /conclusion (prompt JSON)
- POST /send-email

6.4 Pipeline technique detaille
Etape 1: Ingestion
- Verifier extension autorisee (.dcm/.dicom/.png/.jpg/.jpeg)
- Verifier taille max (60 MB)

Etape 2: Normalisation image
- Si DICOM: conversion en PNG 8 bits
- Sinon image directe

Etape 3: Detection/segmentation
- Inference Mask R-CNN
- Filtrage confidence threshold
- Fusion masques overlap meme classe

Etape 4: Classification lesion
- Crop intelligent ROI par bounding box
- Extraction features deep DenseNet+ConvNeXt
- Standardisation features
- Prediction SVM -> Benign/Malignant

Etape 5: Feature engineering interpretables
- Morphology: area, perimeter, circularity, eccentricity
- Intensity: mean, std
- Texture: GLCM homogeneity

Etape 6: Packaging reponse
- Image originale base64
- Image annotee base64
- Image segmentation base64
- Liste predictions individuelles + features

Etape 7: Rapport medical textuel
- Prompt structure a partir des resultats
- Appel /conclusion LLM
- Si echec LLM: fallback rapport local

6.5 Integration backend Spring
- Backend appelle /predict et parse JSON
- Persist metadonnees en DB
- Persist images decodees sur disque (folder unique UUID)
- Expose endpoints detail/historique/report au frontend

6.6 Exigences metriques IA (cible)
- Mesurer precision, recall, F1 par classe lesion
- Mesurer temps moyen inference par image
- Mesurer taux d'echec parsing ou payload
- Versionner modeles utilises a chaque inference

6.7 Risques techniques
- Latence inference sur CPU
- Taille payload base64 elevee
- Variabilite qualite image DICOM
- Faux positifs/faux negatifs

6.8 Mitigations
- Timeouts backend ajustes
- Compression/stockage objet futur
- Monitoring qualite donnees image
- Validation humaine obligatoire avant decision clinique

7) IA #2 PREDICTION RISQUE (METABRIC) - ULTRA DETAILLE
====================================================================
7.1 But fonctionnel
Estimer la probabilite de recurrence cancer du sein a partir de 22+ features
cliniques/molculaires, et retourner un niveau de risque interpretable.

7.2 Stack IA
- FastAPI + Uvicorn
- CatBoost (modele calibre)
- pandas/numpy/scikit-learn
- pydantic validation stricte

7.3 Endpoints IA risque
- GET /health
- GET /dataset-stats
- POST /predict-risk

7.4 Features principales (extraits)
- age_at_diagnosis
- type_of_breast_surgery
- cellularity
- chemotherapy
- pam50_claudin_low_subtype
- er/pr/her2 statuses
- neoplasm_histologic_grade
- tumor_size
- tumor_stage
- lymph_nodes_examined_positive
- mutation_count
- nottingham_prognostic_index
- 3_gene_classifier_subtype

7.5 Pipeline data science d'apprentissage
- Split 3 voies sans fuite: train/val/test
- Tuning Optuna + cross validation
- Calibration probabiliste (Platt)
- Optimisation threshold sur val
- Evaluation finale sur test holdout
- Generation metadata model (version, metrics, threshold, params)

7.6 Metriques actuellement exposees
- AUC test
- F1 test
- Threshold optimise
- Nombre de features utilisees

7.7 Inference runtime
- Charger model + metadata + dataset stats au startup
- Valider payload pydantic (bornes numeric + enums libres)
- Construire dataframe dans ordre exact features
- predict_proba -> probability
- Determiner is_high_risk et risk_level

7.8 Mapping backend -> IA risque
- Backend peut auto-remplir champs depuis PatientProfile/MedicalRecord/Treatment
- Overrides manuels front fusionnes s'ils non nuls
- Conversion enums cliniques vers representation attendue dataset

7.9 Risques et limites
- Distribution drift entre donnees locales et METABRIC
- Variables manquantes ou mappees approximativement
- Seuil optimal dataset peut ne pas etre optimal population locale

7.10 Mitigations
- Monitoring drift data/model
- Recalibration periodique seuil
- Re-entranement avec donnees locales anonymisees et gouvernees
- Validation clinique retrospective avant usage avance

8) IA CHAT EDUCATION (OLLAMA) - ULTRA DETAILLE
====================================================================
8.1 Objectif
Fournir assistance conversationnelle empathique et informative, orientee
education/sensibilisation, sans diagnostic.

8.2 Fonctionnement
- Prompt systeme impose role + regles de securite
- Message utilisateur ajoute a l'historique session
- Enrichissement avec contexte medecins reels verifies
- Appel Ollama /api/chat

8.3 Regles de surete contenu
- Ne jamais diagnostiquer
- Eviter formulations anxiogenes
- Proposer consultation medecin reelle
- Poser question de clarification

8.4 Gestion erreurs technique
- Timeout -> message explicite
- Service indisponible -> 503
- Reponse vide -> erreur controllable

8.5 Limites
- Historique en memoire volatile (perte au restart)
- Pas de moderation medicale avancee multi-niveaux
- Dependance au modele local Ollama

8.6 Evolutions recommandees
- Persister conversation en DB chifree (optionnel)
- Ajouter garde-fous NLP (content safety)
- Ajouter metriques qualite reponses (feedback thumbs up/down)
